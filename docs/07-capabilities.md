# 07 · 现在能在播放器上做到哪些事

按「已实现 / 同一套方法可直接做 / 需要额外工作 / 做不到」四档来分。

---

## A. 已经做到并且验证过的

| 能力 | 状态 | 证据 |
|---|---|---|
| 解析固件容器（解包 / 重打包） | ✅ | `tools/upg.py`，15/15 校验通过 |
| 读 / 写 ext4 镜像（不改元数据） | ✅ | 差异仅 11 个块，元数据零差异 |
| 提取全部 271 个 QML + 图像资源 | ✅ | `tools/dump_resources.py` |
| 原地替换 Qt 内嵌资源 | ✅ | `tools/qtres.py` |
| 菜单弹窗玻璃化 | ✅ | 4 个 QML，8 种配色 |
| 导航栏改色 | ✅ | `NavigationBar.qml` |
| **全局主题改色**（一处生效全 UI） | ✅ | `ScreenSettings.json` 的 `viewstyle.bgcolor` |
| 背景贴图透明化 | ✅ | 3 个 PNG，5 处实例 |
| 设备端 MD5 清单自动同步 | ✅ | 否则写后校验会失败 |
| 独立校验器 | ✅ | `tools/verify.py`，15/15 |

**关键结论**：UI 是**纯 QML 源码**，不是字节码、没有混淆。
所以界面的任何改动，本质上都是「改文本 + 保证塞得进原槽位」。

## B. 同一套方法可以直接做（不需要新工具）

### 1. 把玻璃风格铺到所有界面

现在只改了菜单弹窗 + 导航栏。剩下的都能用同样方式处理：

| 界面 | 对应 QML | 难度 |
|---|---|---|
| 状态栏 | `components/StatusBar*.qml` | 低 |
| 播放界面 | `chunk_9` 下的播放控件 | 中 |
| 文件浏览 / 库视图 | `chunk_9` / `chunk_10` | 中 |
| 设置页 | `chunk_13` / `chunk_14` | 中 |
| 对话框 | `framework/Dialog.qml` | 低 |
| 列表项 | `components/SettingItemNormal.qml` | 低 |

因为全局主题色已经改掉了，大部分界面**已经跟着变深蓝了**，
剩下的主要是把贴图换成带 alpha 的 `Rectangle`。

### 2. 换配色 / 换主题

只改 `tools/theme.py` 里的 `GLASS` 字典：

```python
GLASS = {
    "panel":   "#cc0e2033",   # 面板
    "row":     "#ad122842",   # 行
    "row_sel": "#e01e4a72",   # 选中行
    ...
}
THEME_BG_NEW = '"D1": "#0a1622"'
```

想换成品红、墨绿、紫罗兰都可以，改完重跑 `patch_ui.py` 即可。

### 3. 换图标

`assets/images/` 下的图标都是普通 PNG。替换规则只有一条：
**新的不能比旧的大**。用 `tools/minpng.py` 可以压出极小的纯色 PNG；
彩色图标则需要在同尺寸下重新量化。

### 4. 换字体

QML 里 `font.family` 指向的资源可以替换，前提是塞得进槽位。
中文字体通常很大，实际操作空间有限。

### 5. 调布局

`OptionMenuList.qml` 里有 `cell_height`、`separator_height`、
`bottomSpace` 之类的参数。改这些就能调行高、间距、菜单宽度——
但注意这会改变 `backgroundImage` 的 `anchors` 计算，
改完必须重新验证语法和视觉效果。

## C. 需要额外工作

### 6. 启动画面 / 开机 logo

不在 system 分区里，通常在单独的 logo 分区或 boot 分区。
需要先定位分区布局（`update.sh` 里有线索），再处理对应的镜像格式。
**目前没有做过。**

### 7. 音效参数（EQ / DSEE HX / Clear Phase）

音频处理在 `HgrmMediaPlayerApp` 的机器码里，也有部分参数在
`/vendor/sony/` 下的配置文件里。

* **配置文件层**：如果能找到参数文件（类似 `ScreenSettings.json` 那种），
  改起来和改主题一样简单——但目前**没有确认存在**这样的文件。
* **机器码层**：需要反汇编 ARM 代码、定位 DSP 参数表。
  难度比改 QML 高一个数量级，而且**改错了会直接影响音质甚至爆音**。

### 8. 增加新功能（比如显示歌词、支持新格式）

QML 层可以加纯前端的东西（新面板、新动画、新的显示逻辑）。
但任何需要**新的 C++ 后端能力**的功能（比如解码新格式、
访问新硬件）都必须改 `HgrmMediaPlayerApp` 的机器码——
那会改变二进制长度和所有内部偏移，**风险等级完全不同**。

### 9. 换掉整个 UI

理论上可以写一套全新的 QML 替换 `FrameWork.qml`。
但原厂 QML 依赖大量 C++ 注册的单例（`viewstyle`、`p` 等），
必须先把这些接口全部摸清楚。**工作量很大。**

## D. 做不到 / 不建议做

### 10. Root / 提权

设备端没有验证到可用的 ADB 通道，也没有找到可写的提权路径。
`AdbEnabler` / `AdbDisabler` 这两个程序存在于固件里，
但**不能证明设备端当前开放了 ADB 或 root shell**。

想 root 需要利用系统漏洞或改 boot 分区——那是完全不同的风险等级。

### 11. 读实时内存 / 在设备上调试 UI

需要在设备上跑调试器或 profiling 工具，目前没有可用通道。
所以**所有性能结论都是静态分析得出的**，没有实测帧率。

### 12. 加入流媒体 / 蓝牙新协议

需要新的 C++ 实现，属于第 8 类的极端情况，不现实。

### 13. 直接改音频文件实现「效果」

**这不是界面改造。** 修改 MP3 文件本身是另一回事，
和播放器 UI 无关。

---

## 一句话总结

**能做到的**：把播放器的**视觉层**（配色、透明度、圆角、图标、布局）
改成任何你想要的样子——因为 UI 是纯 QML，且颜色有全局主题入口。

**做不到的**：改功能、加功能、提权、碰音频 DSP。
这些都需要动机器码，风险和难度完全不同。

**当前这版**：菜单 + 导航栏 + 全局主题 + 背景贴图。
视觉上已经统一，剩下的界面主要是「跟着主题色变」和「继续铺玻璃效果」。
