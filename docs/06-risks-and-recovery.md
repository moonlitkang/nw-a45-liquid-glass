# 06 · 变砖风险与恢复

> **没有实机测试过就不要刷。** 静态校验能证明「结构完好、语法正确」，
> 不能证明「渲染效果符合预期」，也不能证明设备一定会接受这个包。

---

## 改动范围

补丁后的 system.img 与原始镜像逐 4096 字节比较：

```
差异块数：11 / 204800
差异范围：0x37E6000 .. 0x3BDD000
归属文件：
  /vendor/sony/bin/HgrmMediaPlayerApp    （10 块）
  /vendor/sony/bin/ScreenSettings.json   （ 1 块）
```

**ext4 元数据（超级块、组描述符、块位图、inode 位图、inode 表）逐字节一致。**

UPG 容器里，除了 sector 1（MD5 清单，有意更新）和 sector 6（system 分区），
其余 7 个 sector 与原厂包**逐字节相同**，加密头部也完全相同。

也就是说：bootloader、recovery、TrustZone、内核、CM4 音频固件、
NVP 参数——**一个字节都没动**。

## 失败模式

### 1. 设备端写后校验失败（中风险，最可能发生）

`update.sh` 的逻辑：

```sh
grep system.img md5.txt
if [ $? -eq 0 ]; then
    fwpup -z ...      # 写入并校验
else
    fwpup ...         # 只写
fi
```

清单里存在 `system.img` 那一行时走「写入并校验」。如果这一行的 MD5 与
实际镜像不符，校验会失败。

**后果**：刷写可能中途中止。由于 system 分区在 sector 6、cm4 在 sector 7、
nvp 在 sector 8，中止意味着后两个都没写——但它们的原值还在，设备大概率
仍能启动到 recovery。

**本项目的处理**：`tools/upg.py` 在打包时自动重算并刷新这一行，
且断言行长不变。`tools/verify.py` 会独立复核「清单 MD5 == 实际解码镜像 MD5」。

### 2. 更糟的分支：分区被清零

同一段脚本里有一个分支会在**校验信息缺失或不匹配**时先清零目标分区再写。
如果设备端的校验规则比我们理解的更严格，理论上可能出现「分区已清零、
新数据没写进去」。

**这是最大的不确定性。** 现有证据只能证明我们构造的包在结构上自洽，
无法证明设备端 `fwpup` 会接受它。

**缓解**：system 分区被清零时，recovery 分区仍完好，可以进入恢复模式。

### 3. QML 语法错误（低风险，但已经发生过一次）

第一版补丁因为文本被截断，末尾大括号丢失，导致菜单组件加载失败。

**后果**：设备能正常开机、能播放音乐，只是菜单打不开。
**不构成变砖**，但体验严重受损。

**本项目的处理**：每个文件写完都做括号平衡 + 结尾检查，
不平衡直接构建失败。

### 4. 渲染异常（低风险）

Qt Quick 对未知属性只警告不报错。如果哪天替换写错了属性名，
可能出现「能开机、菜单能开、但显示不对」。

**后果**：视觉问题，不影响功能。

## 安全机制

| 机制 | 状态 |
|---|---|
| 官方升级器签名校验 | **已关闭**（`AssistFile.ini` 里 `UseSonyCheck=0`） |
| 设备端写后 MD5 校验 | 存在，本项目已同步清单 |
| 自动回滚 | 无 |
| A/B 分区 | 无 |
| Recovery 模式 | 有（未改动） |
| 官方完整刷机包 | 有，可完全恢复 |

## 恢复路径

### 首选：用官方升级器刷回

1. USB 连接设备；
2. 运行原厂 `NW-A40_V1_10.exe`（或解包后的 `SoftwareUpdateTool.exe`）；
3. 等待完成。

因为 `UseSonyCheck=0`，同版本重刷不会被拒。这是最可靠的恢复方式。

### 备选：进恢复模式

设备开机时按特定组合键可进入恢复模式（NW-A45 是 **电源键 + 音量减**，
具体以官方说明为准）。进入后可以：
* 重置设置；
* 在部分固件版本上执行系统修复。

如果 system 分区已损坏到无法挂载，恢复模式仍能工作——因为它跑在
未改动的 recovery 分区上。

### 最后手段：设备端强制刷写

如果 recovery 也进不去（概率很低，因为 recovery 分区没动），
就只能走 Sony 官方维修流程。

## 刷机前检查清单

- [ ] 电量 ≥ 50%
- [ ] 设备本机剩余空间 ≥ 200 MB
- [ ] 已用官方升级器确认当前固件版本是 1.10
- [ ] 已备份播放列表 / 书签 / 设置（音乐文件本身在存储卡上，不受影响）
- [ ] 已保留原始 `NW_WM_FW.UPG` 副本
- [ ] 手边有可用的 USB 线（刷写中不能断）
- [ ] 已读过 [docs/04](04-patch-strategy.md) 和本文档

## 刷机中

* **不要拔 USB 线**；
* **不要按任何按键**；
* 设备会自动关机再开机，Windows 可能弹「USB 设备已断开」——**这是正常的**；
* 写 800 MB 的 system 分区大约需要 1–3 分钟。

## 刷机后验证

1. 设备能正常开机到主界面 → 基本可用；
2. 按「…」键 → 菜单应该弹出，且是半透明深蓝圆角面板；
3. 播放一首歌 → 音频链路正常；
4. 进设置 → 本机信息 → 版本号应仍为 1.10。

如果第 2 步菜单不弹，说明 QML 没被重新加载（缓存或改法问题），
不影响其他功能，可以刷回原厂。
